# TQP-Vortex test suites

`tests/` is the correctness suite: pytest unit tests per component, the SF1
smoke (all 22 queries against `tests/verification/`) and the e2e ladder (the
modes and cache policies end to end). A change is correct when they pass. Tests
assert results, never timings: performance is measured by the experiments in
`experiments/self-verification/` (`e2_speedup.py`, an in-process A/B;
`e5_time_breakdown.py`, an Nsight trace), not here.

`tests/conftest.py` bootstraps the custom CUDA allocator **once per process**,
so the suites can run together — no test swaps the allocator itself. It also
restores the telemetry and debug switches (`IO/telemetry/gates.py`) after every test,
and its `telemetry` fixture (`telemetry(experiment=True)`) is how a test turns
on the movement ledger and the other experiment numbers it reads. The arena
is sized to the production default (22 GB) so the smoke suite's full-engine run
fits. GPU-dependent tests skip on a CPU-only box. The SF1 suites (smoke, e2e)
take the SF1 dataset from the `sf1_parquet` session fixture, the data root
holding `sf1/parquet`; a GPU box without it fails loudly rather than
skipping, and the failure says how to make it (`make data SF=1`).

The e2e suite runs one `main.py` subprocess per cell next to the session
arena, so it needs roughly 44 GB of free GPU memory.

## Running

```bash
python test.py                  # all suites
python test.py tests/allocator  # one suite (or any path)
python test.py -k lend          # forward any pytest flags
python test.py -m "not e2e"     # skip the ~2.5 min adaptive-flag ladder and the UVM cells

# equivalently, straight pytest:
pytest tests/
```

The smoke suite (SF1 correctness only) is also runnable on its own via:

```bash
python main.py --smoke
```

## The SF1 reference

`tests/verification/SF1_reference.out` holds DuckDB's answers to the 22 queries
on the standard SF1 data, every row, rendered as `main.py` writes
`results.out`: per query, pandas `to_string()` of the result under TQP-Vortex's
column names and in its column order, integers as integers and every other
number to six decimals. The smoke suite compares with it at 10 significant
figures and the e2e ladder at 6 (integers exactly), through
`tests/sigfig_compare.py`: the headers in order, each result's rows in any
order.

It was made with one-off scripts, kept out of the repo. DuckDB 1.5.5 (the
baselines' image) ran the baselines' query stream,
`baselines/results/queries/stream_qualification.sql`, read through
`stream.py`'s `queries(1)` (so q11's FRACTION is 0.0001), over views on
`$DATA_DIR/sf1/parquet`. DECIMAL values
were written exactly, DOUBLE values rounded to six decimals. Each column's name,
position and kind (integer or not) came from TQP-Vortex's own `results.out` on
the same data. Make it again the same way when the data or a query changes. The
file holds nothing but the results: any other line would count as a result.
